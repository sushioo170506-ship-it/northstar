# model-report-playbook

基于高质量长篇样稿沉淀的“可复用模块”，用于增强各 step skill 的可执行性。

## 1) 结构模块（推荐固定）
- 背景与目标
- 模型介绍（定位、技术路线、能力边界、应用落地、安全治理）
- 横向对比（能力/技术路线/组织治理）
- 局限与风险（能力边界/安全边界/使用边界）
- 战略启示（趋势、影响、行动）
- 参考资料（来源分层、时间戳、可信度）

## 2) 技术拆解模块（三段式）
每条技术路线建议按以下模板写：
1. 现象/可观测信号  
2. 学术溯源（论文、方法族、时间脉络）  
3. 本质分析（为何有效、边界、失败模式）

## 3) 双轨分析模块（能力 + 治理）
对关键结论同时输出：
- 能力轨：模型是否“能做”
- 治理轨：模型是否“可安全可持续地做”

## 4) 对比模块（不只 benchmark）
最少覆盖四类对比：
- 能力对比（benchmark/任务表现）
- 成本对比（定价、token、总体拥有成本）
- 部署对比（可用性、延迟、工具支持、访问限制）
- 治理对比（安全机制、分级访问、合规约束）

## 5) 决策模块（必须可执行）
- 场景化推荐表（推荐/有条件推荐/不推荐）
- 加权评分卡（维度、权重、得分、解释）
- 路线图（30/60/90 或 90 天）
- 退出条件（Fail Fast）

## 6) 风险模块（标准字段）
风险登记表建议字段：
`risk, severity, trigger, impact, mitigation, owner, status`

## 7) 证据模块（复核必备）
- `source_index.csv`
- `evidence_map.csv`
- `evidence_ledger.csv`
- `benchmark_master_table.*`
- `competitor_matrix.*`

## 8) 常见减分项（供 Step6 直接判罚）
- 只有观点没有证据链
- 只讲能力不讲治理
- 对比口径混乱
- 没有局限声明
- 没有行动计划与退出机制
