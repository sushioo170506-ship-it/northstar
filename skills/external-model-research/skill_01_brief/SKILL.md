# mr-step1-scope

name: mr-step1-scope  
description: Step 1 — 明确读者画像、报告定位和结论形式，为后续步骤设定取舍标准。

## 作用
确定报告方向和约束。后续所有步骤据此做取舍；这一步不确定的内容，后续会反复纠结。

## 输入
- 模型名称（例如 `DeepSeek-V3`）
- 用户必须回答 3 个问题：

### Q1: 谁看这篇报告？
- 技术选型团队（做技术决策）
- 管理层（做投资/战略决策）
- 安全审查组（做合规判断）
- 客户（做采购决策）
- 泛技术社区（做科普了解）

### Q2: 看完要做什么？
- 选型：用不用这个模型？什么场景用？
- 投资：值不值得关注/投入资源？
- 安全：能不能引入？有什么风险？
- 认知：了解模型技术特点
- 追踪：监控竞品动态

### Q3: 最怕出什么问题？
示例：数据不准确导致选型错误；漏掉关键风险点；篇幅过长没人看。

## 输出（报告企划书）
写入 `archive/scope.md`，结构如下：

```md
# 报告企划书 — [模型名称]

## 读者画像
- 主要读者: [角色]
- 决策类型: [选型/投资/安全/科普/追踪]
- 阅读场景: [具体场景]
- 核心担忧: [最怕的问题]

## 报告参数
- 报告类型: [技术选型 / 安全审查 / 投资研判 / 竞品追踪 / 科普介绍]
- 篇幅: [长篇详实(3000-5000字) / 简报(1000-2000字) / PPT速览(3-5页)]
- 风格: [严谨技术风 / 决策简报风 / 面向客户]
- 结论形式: [推荐/有条件推荐/不推荐 或 绿/黄/红]

## 约束条件
- 必须包含: [...]
- 可以忽略: [...]
- 截止时间: [YYYY-MM-DD]
```

## 质量卡口
- 三个问题均有回答，无空白项。
- 读者画像具体到角色和决策场景（非泛称）。
- 报告类型明确（5 选 1）。
- 结论形式明确（可执行判定）。
- 明确报告深度档位（长篇/简报/PPT）并写入 scope。
- 明确“最低信息密度要求”（例如：最少来源数、最少表图数），供后续步骤继承。

## 交接
将 `archive/scope.md` 交给 `mr-step2-outline`。
