# mr-step1-scope

name: mr-step1-scope
description: Step 1 — 定义调研任务边界，明确读者、目标、结论框架与信息门槛。

## 定位与作用
本步骤是“定调层”，用于回答“这份报告到底要服务谁、解决什么问题、做到什么深度”。  
如果 scope 不清晰，后续再多信息也容易变成“内容很多、结论不可用”。

## 输入
- 模型名称（例如 `GPT-5.6`）
- 读者与场景信息（至少覆盖 2 类组织）
- 分析目标与核心风险

## 读者与场景示例（可选）
可从以下类型中组合：
- 技术选型、管理决策、安全审查、采购合规、运维平台、业务产品；
- 政府/事业单位、监管与标准组织、技术合作团队、生态合作伙伴；
- 典型场景如立项评审、采购论证、监管沟通、合作对接、上线门禁评审。

## 输出
写入 `archive/scope.md`，最少包含以下块：
1. 读者画像（角色、场景、核心担忧）
2. 报告参数（类型、篇幅、风格）
3. 结论输出框架（定位/能力/场景/边界/启示）
4. 丰富度门槛（来源/竞品/benchmark/表图/文献）
5. 约束条件（必须包含、可忽略、截止时间）
6. `核心结论假设清单`（每条包含：`conclusion_id`、结论假设、决策价值）
7. `过程-成果预期清单`（每个分析过程对应预期成果和价值）

## 关键差异点
与通用“推荐/不推荐”模板不同，本步骤要求先锁定“模型画像”框架：  
定位与启示是主线，评级只是可选输出，不应替代完整结论结构。

## 执行动作
1. 提取核心读者与阅读场景；
2. 明确分析目标与核心风险；
3. 固化结论五要素框架；
4. 设定可量化的信息密度门槛；
5. 为每个核心结论预设“所需证据类型与推导路径”；
6. 为每类分析过程预设“预期成果与决策价值”；
7. 生成并保存 `archive/scope.md`。

## 逻辑链条要求
Step1 不直接下最终结论，但必须搭好后续推导骨架：
- 结论侧骨架：`结论假设 -> 证据需求 -> 推导方法 -> 预期价值`
- 过程侧骨架：`分析过程 -> 预期成果 -> 决策价值 -> 对应结论假设`

建议在 `scope.md` 使用两张短表固化上面两条链路，避免后续章节出现“只写结论”或“只写过程”。

## 质量卡口
- 关键问题回答完整，无空白项；
- 读者与场景具体，不使用泛化描述；
- 结论五要素齐全：定位、能力、场景、边界、启示；
- 丰富度门槛可量化（非“尽量多”）；
- 若有参考样稿，已写明对齐维度（结构/密度/证据标准）；
- 每条核心结论假设均有证据需求与推导方法；
- 每个关键分析过程均定义预期成果与价值，不得只写“会分析”。

## 交接
将 `archive/scope.md` 交给 `mr-step2-outline`。
