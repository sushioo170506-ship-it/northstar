# mr-step1-scope

name: mr-step1-scope
description: Step 1 — 明确读者画像、决策目标、交付形态与“信息丰富度门槛”，为后续全流程设定硬约束。

## 作用
确定报告方向、决策口径和深度门槛。  
本步骤输出不清晰，会导致后续“有内容但不可决策”。

## 输入
- 模型名称（例如 `DeepSeek-V3`）
- 用户必须回答 3 个问题：

### Q1: 谁看这篇报告？
- 技术选型团队（做技术决策）
- 管理层（做投资/战略决策）
- 安全审查组（做合规判断）
- 客户（做采购决策）
- 泛技术社区（做科普了解）

### Q2: 看完要做什么？
- 选型：用不用这个模型？什么场景用？
- 投资：值不值得关注/投入资源？
- 安全：能不能引入？有什么风险？
- 认知：了解模型技术特点
- 追踪：监控竞品动态

### Q3: 最怕出什么问题？
示例：数据不准确导致选型错误；漏掉关键风险点；篇幅过长没人看。

## 输出（报告企划书）
写入 `archive/scope.md`，结构如下：

```md
# 报告企划书 — [模型名称]

## 读者画像
- 主要读者: [角色]
- 决策类型: [选型/投资/安全/科普/追踪]
- 阅读场景: [具体场景]
- 核心担忧: [最怕的问题]

## 报告参数
- 报告类型: [技术选型 / 安全审查 / 投资研判 / 竞品追踪 / 科普介绍]
- 篇幅: [长篇详实(8000-15000字) / 简报(1500-3000字) / PPT速览(5-10页)]
- 风格: [严谨技术风 / 决策简报风 / 面向客户]
- 结论形式: [推荐/有条件推荐/不推荐 或 绿/黄/红]

## 丰富度门槛（必须写）
- 最少来源数: [>=25]
- 最少官方来源: [>=8]
- 最少第三方来源: [>=10]
- 最少竞品数: [>=5]
- 最少 benchmark 指标: [>=25]
- 最少表格数: [>=12]
- 最少图表数: [>=4]
- 最少参考文献数: [>=30]
- 是否要求 90 天行动路线图: [是/否]
- 是否要求加权评分卡: [是/否]

## 约束条件
- 必须包含: [...]
- 可以忽略: [...]
- 截止时间: [YYYY-MM-DD]
```

## 质量卡口
- 三个问题均有回答，无空白项。
- 读者画像具体到角色和决策场景（非泛称）。
- 报告类型明确（5 选 1）。
- 结论形式明确（可执行判定）。
- 明确报告深度档位（长篇/简报/PPT）并写入 scope。
- 已明确“丰富度门槛”，且门槛值可量化（不是“尽量多”）。
- 明确是否强制输出“风险映射表、评分卡、行动路线图”。
- 若用户提供参考样稿，已在 scope 中写明“对齐样稿丰富度”的约束。

## 交接
将 `archive/scope.md` 交给 `mr-step2-outline`。
