# mr-step2-outline

name: mr-step2-outline
description: Step 2 — 构建高信息密度报告骨架，明确章节结构、证据门槛与表图计划。

## 作用
大纲是“信息生产蓝图”，不是目录草稿。  
必须提前锁定每章证据数、表图数、核心判断与缺失回补策略。

## 输入
- `archive/scope.md`（Step 1 产出）
- 模型名称

## 输出
写入 `archive/outline.md`（章节大纲，含素材需求与图表需求标注）。

## 复用模块来源
- 结构与模块优先对齐：`skills/external-model-research/model-report-playbook.md`

## 预设骨架（按报告类型选择）
- 骨架 A：技术选型型（§1 模型全景 ... §7 结论与建议）
- 骨架 B：安全审查型（来源、版权、安全、偏见、合规、处置）
- 骨架 C：投资研判型（定位、护城河、团队、商业化、竞品、风险、判断）
- 骨架 D：竞品追踪型（版本增量、升级点、评测对比、影响、跟踪项）

## 推荐长篇章节（对齐高丰富度样稿）
- 〇 调研背景与目的
- 一 模型介绍（定位、技术路线、能力边界、场景落地、安全治理）
- 二 横向对比（能力/技术路线/组织治理）
- 三 局限与风险（能力边界/安全边界/使用边界）
- 四 战略启示（趋势、影响、行动建议）
- 参考资料（分级来源，带时间戳）

## 裁剪规则
- 简报型：可合并 `§1+§2`、`§3+§4`，保留 §7。
- 管理层读者：弱化技术细节，强化对标和结论。
- 技术读者：强化技术拆解和评测细节。
- 安全审查类：使用骨架 B，忽略非必要选型维度。
- 政府/监管读者：强化治理机制、风险分级、合规约束与政策影响。
- 技术合作团队：强化接口能力、协同边界、联合落地前提与分工。
- 采购/招投标读者：强化成本、可用性、交付与SLA相关证据。

## 章节标注模板
```md

核心问题: 这一章要解决什么问题？
目标读者: [技术/管理/政府/合作/采购...]
篇幅权重: xx%
素材需求:
  - ...
需要生成的图表:
  - ...
本章最低证据数:
  - ...
本章最低数据表:
  - ...
本章必须产出:
  - [判断句列表]
  - [证据映射id范围]
```

## 深度门槛（大纲阶段即锁定）
- `长篇详实` 默认要求：
  - 一级章节数：>= 5（不含参考资料）
  - 二级小节数：>= 18
  - 关键证据点：>= 40
  - 表格计划：>= 12
  - 图表计划：>= 4
  - 关键结论数：>= 12
- 每章必须标注 `最低证据数`，否则大纲不通过。

## 强制表图规划（长篇）
至少提前规划以下四类可交付图表：
1. benchmark 总览矩阵
2. 竞品能力对照表
3. 风险-影响-缓解映射表
4. 决策评分卡或路线图表

## 质量卡口
- 已根据报告类型选择预设骨架。
- 已按读者画像与篇幅约束裁剪。
- 每章均标注核心问题。
- 每章均标注素材需求。
- 需要图表的章节均提前标注。
- 每章均标注“最低证据数”和“至少一个可交付内容块”（表/图/要点卡）。
- 每章均标注“目标读者”，且覆盖 scope 中的关键人群。
- 长篇模式下，表图计划达到 scope 设定门槛（默认表>=12、图>=4）。
- 章节权重与读者目标一致（例如管理层版本突出结论与行动）。
- 已明确哪些章节需要“风险映射、评分卡、行动计划”。
- 已标注“双轨分析”章节（能力轨 + 治理轨）。
- 已标注“技术三段式拆解”章节（现象 -> 溯源 -> 本质）。
