# mr-step5-write

name: mr-step5-write
description: Step 5 — 用结构化证据完成正文写作，输出可被多角色直接使用的模型画像报告。

## 定位与作用
本步骤是“表达成稿层”。  
核心目标不是堆信息，而是把证据组织成清晰、可追溯、可执行的结论链。

## 输入
- `archive/processed_data/`
- `archive/outline.md`
- `archive/scope.md`

## 输出
- `archive/report.md`

## 长篇写作门槛
- 篇幅目标：8000-15000 字（如 scope 指定更高，按 scope 执行）；
- 全文引用表格 >= 12，图表规格 >= 4；
- 核心章节（§2-§6）每章至少包含：判断句 + 证据 + 解读 + 局限。

## 写作方法
1. 按“能力证据优先”的章节顺序写作；
2. 每段首句声明段落职能（判断/对比/解读/行动）；
3. 关键数字必须配解释，不做“裸数据”陈列；
4. 技术部分采用三段式（现象/溯源/本质）；
5. 关键章节体现双轨分析（能力轨/治理轨）；
6. 关键段落使用 CERV 句式：先给结论，再给证据与推导，最后落到价值与边界；
7. 每个过程型小节末尾必须有“本节成果与价值”小结，不得只记录流程描述。

## 逻辑链条落稿规范
为避免“结论空心化”和“过程悬空化”，正文必须满足：
1. 每条核心结论至少对应 1 个 `conclusion_id` 与 2 条可回链证据；
2. 每个关键过程章节（采集、加工、评测、治理设计等）末尾都要明确：  
   - 本节达成了什么成果；  
   - 该成果支撑了哪个结论；  
   - 对业务决策带来什么价值；
3. 章节内部推荐使用小模板：  
   `结论句 -> 证据摘要 -> 推导说明 -> 局限说明 -> 动作建议`

## 结论章节（§7）必备结构
- 模型定位
- 能力判断
- 场景结论（适用/不适用/前提）
- 效果与边界
- 启示与动作
- 90 天路线图
- 加权评分卡（可选附评级）

## 质量卡口
- 结论五要素齐全；
- 所有核心结论可回链证据；
- 文风与目标读者匹配；
- 每个过程型小节均有“成果与价值”结论句；
- 结论与过程双向可映射，不存在孤立段落；
- 若证据密度不足，回退 Step4 补证据块后重写。

## 交接
将 `archive/report.md` 交给 `mr-step6-review`。
