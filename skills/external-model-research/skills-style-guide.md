# External Model Research Skills Style Guide

本规范用于统一 `external-model-research` 下所有 skill 文档的写作结构、术语和排版风格。  
目标是：**结构一致、信息聚焦、可读性高、可直接执行**。

## 1. 文档结构模板（必须）

每个 skill 文档应按以下顺序组织：
1. `# skill-name`
2. `name` / `description`
3. `## 定位与作用`
4. `## 输入`
5. `## 输出`
6. `## 方法/执行动作`（可按需要命名为“采集原则”“写作方法”等）
7. `## 差异化说明`（与上下游步骤的边界）
8. `## 质量卡口`
9. `## 回退策略`（若该步骤有回退逻辑）
10. `## 交接`

> 允许按步骤特性增减 1-2 个小节，但不得省略“定位与作用、输入、输出、质量卡口、交接”。

## 2. 文风要求（必须）

- 解释优先：先说明“为什么”，再给规则。
- 少堆术语：术语首次出现给简短解释。
- 一段一意：每段尽量只承载一个核心信息。
- 避免空话：禁止“高质量、全面、系统”等无验收含义的泛化描述单独成句。

## 3. 术语统一（必须）

- 统一使用：`定位/能力/场景/边界/启示`（结论五要素）
- 统一使用：`能力轨/治理轨`（双轨分析）
- 统一使用：`现象/溯源/本质`（技术三段式）
- 统一使用：`质量卡口`、`回退策略`、`交接`
- 统一使用：`CERV`（结论->证据->推导->价值/边界）
- 统一使用：`PEVC`（过程->成果->价值->对应结论）

## 3.1 逻辑链条闭环（必须）

每个 skill 文档都应显式说明以下至少一项：
1. 如何保证结论不是“只报答案不报依据”；
2. 如何保证过程不是“只记步骤不出结果”。

推荐写法：
- 结论闭环：`结论 -> 证据 -> 推导 -> 价值/边界`
- 过程闭环：`过程 -> 成果 -> 价值 -> 对应结论`

禁止出现以下表达方式：
- 只有“建议/结论”但无数据依据与推导说明；
- 只有“采集/分析过程”但无最终成果与价值说明。

## 4. 表格与文字比例（建议）

- 表格只承载结构化字段，不替代解释文字。
- 每张关键表格前后至少有 1 段解释其用途、口径与限制。
- skill 文档中优先使用短列表；仅在必须对齐字段时使用表格。

## 5. 去冗余规则（必须）

- 通用定义不在每个文档重复，优先引用：
  - `model-report-playbook.md`
  - `model-report-rubric.yaml`
- 阈值只保留“当前步骤必需”的部分，不重复完整工作流所有门槛。
- 与本步骤无关的流程细节，移至 orchestrator 或 workflow.yaml。

## 6. 可执行性要求（必须）

- 输入字段要能落地到文件或参数；
- 输出文件名要明确；
- 质量卡口可检查（可量化或可判定）；
- 回退条件与目标步骤明确。

## 7. 变更维护原则

- 修改任一门槛时，需同步检查：
  1) 对应 skill 文档  
  2) `external-model-research-workflow.yaml`  
  3) smoke test 脚本  
- 保持 README 中的阈值与 workflow.yaml 一致，避免多口径。
