# Step 1: 定调

本步骤确定报告方向和约束。后续所有步骤都据此取舍：读者是谁、看完要做什么、最怕出什么问题。

## 输入

- 模型名称，如 `DeepSeek-V3`。
- 用户必须回答 3 个问题：

```text
Q1: 谁看这篇报告？
    □ 技术选型团队（要做技术决策）
    □ 管理层（要做投资/战略决策）
    □ 安全审查组（要做合规判断）
    □ 客户（要做采购决策）
    □ 泛技术社区（要做科普了解）

Q2: 看完要做什么？
    □ 选型：用不用这个模型？什么场景用？
    □ 投资：值不值得关注/投入资源？
    □ 安全：能不能引入？有什么风险？
    □ 认知：了解这个模型的技术特点
    □ 追踪：监控竞品动态

Q3: 最怕出什么问题？
    例：怕数据不准确导致选型错误 / 怕漏掉关键风险点 / 怕篇幅太长没人看
```

如果用户未显式回答，先给出这三个问题；如任务要求继续推进，可基于上下文做保守假设，但必须在企划书中标注"假设"。

## 输出：报告企划书

生成 `report_scope.md`，格式如下：

```markdown
# 报告企划书 -- [模型名称]

## 读者画像
- 主要读者: [具体角色]
- 决策类型: [选型/投资/安全/科普/追踪]
- 阅读场景: [例：团队晨会前10分钟扫完 / 作为附件发给客户]
- 核心担忧: [最怕出什么问题]

## 报告参数
- 报告类型: [技术选型 / 安全审查 / 投资研判 / 竞品追踪 / 科普介绍]
- 篇幅: [长篇详实(3000-5000字) / 简报(1000-2000字) / PPT速览(3-5页)]
- 风格: [严谨技术风 / 决策简报风 / 面向客户/非技术人员]
- 结论形式: [推荐/有条件推荐/不推荐 + 理由 / 绿/黄/红 + 处置建议]

## 约束条件
- 必须包含: [例：实测数据 / 成本分析 / 安全评估]
- 可以忽略: [例：训练细节 / 历史沿革]
- 截止时间: [YYYY-MM-DD]
```

## 映射规则

| 读者/目的 | 默认报告类型 | 默认风格 | 默认结论形式 |
|---|---|---|---|
| 技术选型团队 + 选型 | 技术选型 | 严谨技术风 | 推荐/有条件推荐/不推荐 + 理由 |
| 管理层 + 投资 | 投资研判 | 决策简报风 | 关注/观望/不建议投入 + 理由 |
| 安全审查组 + 安全 | 安全审查 | 审查清单风 | 绿/黄/红 + 处置建议 |
| 客户 + 采购 | 技术选型或客户简报 | 面向客户/非技术人员 | 推荐/有条件推荐/不推荐 |
| 泛技术社区 + 认知 | 科普介绍 | 清晰解释风 | 核心判断 + 关键看点 |
| 竞品/产品团队 + 追踪 | 竞品追踪 | 决策简报风 | 影响判断 + 关注清单 |

## 质量卡口

- [ ] 三个问题都已回答，没有空白；如为假设，已明确标注。
- [ ] 读者画像具体到角色和决策场景，不是"技术团队"这种泛称。
- [ ] 报告类型明确，能从 5 种中单选。
- [ ] 结论形式明确（推荐/有条件推荐/不推荐、绿/黄/红等）。

未通过时，不得进入 Step 2。
