# Step 2: 搭大纲

大纲不是最终目录，而是"为了回答 Step 1 的核心问题，我需要收集什么信息、按什么顺序呈现"的结构化方案。

## 输入

- `report_scope.md`（Step 1 产出）
- 模型名称

## 输出

生成 `outline.md`：章节大纲，包含每章的核心问题、篇幅权重、素材需求和图表需求。

## 预设骨架

### 骨架 A：技术选型型

```markdown
§1 模型全景
  - 基本信息：发布时间、机构、参数量、架构类型
  - 定位：对标什么模型、什么价位、什么场景
  素材需求: [模型卡/论文/官网]

§2 技术拆解
  - 架构创新（区别于 baseline 的关键设计）
  - 训练方法（数据构成、训练策略）
  - 推理优化（量化/蒸馏/vLLM 等）
  素材需求: [论文技术细节/config/技术博客]

§3 能力评测
  - 标准 benchmark（MMLU/HumanEval/GSM8K 等）
  - 专项能力（长上下文/多语言/工具调用）
  - 与官方声称的差异分析
  素材需求: [官方评测/第三方榜单/社区实测]

§4 横向对标
  - 与同类模型的关键维度对比矩阵
  - 性价比分析（能力/成本/推理速度）
  素材需求: [竞品数据/对比表格]

§5 部署分析
  - 硬件需求（显存、GPU 型号、最低配置）
  - 推理效率（延迟、吞吐量、性价比）
  - 部署方案（本地/云端/API）
  素材需求: [硬件实测/官方文档/社区报告]

§6 生态与开放性
  - 开源协议及商用限制
  - 社区活跃度、周边生态
  - 可复现性（checkpoint/代码/配置是否完整）
  素材需求: [License/GitHub/HuggingFace/社区讨论]

§7 结论与建议
  - 适用场景推荐
  - 风险提示
  - 综合评级
  素材需求: [前六章的分析汇总]
```

### 骨架 B：安全审查型

```markdown
§1 模型基本信息与来源
§2 训练数据透明度与版权风险
§3 安全对齐与红队测试
§4 偏见与公平性评估
§5 部署安全风险（越狱/注入/数据泄露）
§6 合规性评估（各地法规）
§7 结论与处置建议
```

### 骨架 C：投资研判型

```markdown
§1 模型定位与市场空间
§2 技术差异化与护城河
§3 团队与资源背景
§4 商业化进展与客户案例
§5 竞品格局与替代风险
§6 风险因素
§7 投资判断
```

### 骨架 D：竞品追踪型

```markdown
§1 模型档案（与前代/前版本的增量变化）
§2 关键升级点
§3 评测对比（与前代 vs 与主要竞品）
§4 影响分析（对市场格局/技术路线的影响）
§5 关注要点（下一步值得跟踪的方向）
```

科普介绍型可从 A 中裁剪：弱化部署/评测细节，强化概念解释、技术特点和影响判断。

## 大纲裁剪规则

| 情况 | 处理 |
|---|---|
| 字数受限（简报型） | §1+§2 合并，§3+§4 合并，保留 §7 |
| 读者是管理层 | 弱化 §2 技术细节，强化 §4 对标和 §7 结论 |
| 读者是技术团队 | 强化 §2 技术拆解和 §3 评测细节 |
| 安全审查类型 | 使用骨架 B，忽略技术选型的部分维度 |

## 大纲标注格式

每个章节必须按以下格式输出：

```markdown
## §3 能力评测
核心问题: 这个模型在主流 benchmark 上表现如何？与官方声称一致吗？
篇幅权重: 15%（全文 ~3000 字，本节 ~450 字）
素材需求:
  - 官方技术报告的 benchmark 表格
  - Open LLM Leaderboard 等第三方榜单
  - 社区实测数据（LMSYS、Reddit、知乎）
  - 与同参数级模型的对标分数
需要生成的图表:
  - 多模型 benchmark 对比柱状图
  - 官方 vs 第三方评测差异表
```

## 质量卡口

- [ ] 已根据报告类型选择对应预设骨架。
- [ ] 已根据读者画像和篇幅约束裁剪章节。
- [ ] 每个章节标注了核心问题。
- [ ] 每个章节标注了素材需求。
- [ ] 有需要生成图表的章节已提前标注。

未通过时，回退 Step 1 或继续修正大纲，不得进入 Step 3。
