# Step 5: 写正文

把加工好的结构化内容块（表格、图表、要点）串成连贯报告。结论在写作过程中自然形成：分析写到位了，结论会浮出来。

## 输入

- `processed_data/`（Step 4 产出）
- `outline.md`（Step 2 产出）
- `report_scope.md`（Step 1 产出，用来控制风格、篇幅和结论形式）

## 输出

- `report.md`：完整报告正文。

## 写作规则

### 规则 1：按依赖顺序写章节

不要从 §1 机械写到结尾。按素材与分析依赖顺序写：

1. 先写 §3 能力评测（素材最全，最容易形成判断）。
2. 再写 §2 技术拆解（解释能力来源）。
3. 然后写 §4 横向对标（需要 §2+§3 支撑）。
4. 然后写 §5 部署分析（相对独立）。
5. 然后写 §6 生态评估（相对独立）。
6. 然后写 §1 模型全景（基础信息，放在前面但最后写更准）。
7. 然后写 §7 结论与建议（汇总前面全部分析）。
8. 最后写 Executive Summary（此时对全文最清楚）。

如果使用非技术选型骨架，也遵循"先写证据最强的分析章节，再写总览和摘要"的原则。

### 规则 2：每段一个职能

段首第一句声明本段职能：

```text
本文的核心发现是：……                    -> 判断段
数据显示，……                            -> 发现段
与该发现形成对照的是，……                 -> 对比段
这意味着……                              -> 解读段
需要指出，本文的分析在以下方面存在局限：…… -> 局限段
如果你的角色是技术选型者，……             -> 行动段
```

### 规则 3：数据不能裸奔

每个关键数字出现后，紧跟一句"这意味着"型解读。

```markdown
❌ Llama 4 的 MMLU 分数为 87.2。

✅ Llama 4 的 MMLU 分数为 87.2（Llama 4 技术报告, 2025），
比 DeepSeek-V3 的 88.5 低 1.3 个百分点。
这意味着在标准知识推理任务上，两者处于同一梯队，
差距不足以构成选型中的决定性因素。
```

### 规则 4：结论嵌入正文

§7 结论与建议就是结论章节，不要在全文之外再单独"下结论"。§7 写法：

```markdown
## 结论与建议

### 综合评估
汇总前六章的核心发现，给出总体评价。

### 适用场景推荐
| 场景 | 推荐模型 | 理由 |
|---|---|---|
| X 场景 | 模型 A | 因为…… |
| Y 场景 | 模型 B | 因为…… |

### 风险提示
- 风险点 1：[描述] + [影响程度]
- 风险点 2：[描述] + [影响程度]

### 综合评级
[推荐 / 有条件推荐 / 不推荐] + [一句话理由]
```

### 规则 5：开篇规则

禁止以下开头：
- "随着……的发展"
- "近年来"
- "XX 是一个重要的……"

必须以下列方式之一开头：

**A. 反直觉数字**

```text
DeepSeek-V3 以 671B 总参量实现 88.5 的 MMLU——
比参数量仅为它 60% 的 Llama 4 仅高 1.3 个百分点。
这个数据揭示了一个反直觉的事实：参数量不是一切。
```

**B. 认知冲突**

```text
开源模型的性能真的追平闭源了吗？
DeepSeek-V3 的数据说"是"，但我们的分析显示
这个"是"前面有三个重要的星号。
```

**C. 直接结论**

```text
如果只用一个结论概括 DeepSeek-V3：
它是目前开源模型中最强的基线选择，但部署成本
是它最大的采用障碍。
```

## 质量卡口

- [ ] 章节约按依赖顺序书写，而不是从 §1 线性写到结尾。
- [ ] 每段段首声明职能。
- [ ] 每个关键数字有"这意味着"型解读。
- [ ] 开篇不是背景铺垫。
- [ ] 结论章节包含具体场景推荐，不模棱两可。
- [ ] 全文风格与 `report_scope.md` 一致。

未通过时，继续修改 `report.md`，不得进入 Step 6。
