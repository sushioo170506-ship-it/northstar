# Step 6: 复核

复核不是"再读一遍"，而是按清单逐项检查，并决定是否回退。严重问题必须回退，不能靠一句免责声明糊过去。

## 输入

- `report.md`（Step 5 产出）
- `report_scope.md`（Step 1 产出，用于检查是否达到目标）

## 输出

- `review_checklist.md`：逐项通过/不通过 + 修正建议 + 是否必须回退。

## 复核维度

### 维度 1：事实性检查

- [ ] 所有数字标注了来源（机构/年份/链接）。
- [ ] 官方数据与第三方数据已区分，如"官方声称 X，第三方复现为 Y"。
- [ ] 无"大约""可能""据说"等未经核实的表述；如确需不确定表述，已说明依据。
- [ ] 引用格式统一。

### 维度 2：完整性检查

- [ ] 覆盖了大纲中所有章节。
- [ ] 每个章节回答了该章的核心问题。
- [ ] 缺失的数据已标注"数据暂缺"而非假装不存在。
- [ ] 结论章节包含具体场景推荐。

### 维度 3：读者视角检查

- [ ] 目标读者能看懂；专业术语已解释。
- [ ] 目标读者看完能做他需要做的事（选型/判断/采购/审查/追踪）。
- [ ] 篇幅在企划书约定范围内。

### 维度 4：逻辑一致性检查

- [ ] §1-§6 的分析支持 §7 的结论，没有"正文说 A 好，结论说 B 好"。
- [ ] 没有未声明的研究局限。
- [ ] 对比维度一致，没有 A 模型用官方数据、B 模型用第三方数据的不公平对比。

### 维度 5：写作质量检查

- [ ] 无禁止词汇或空泛表达，如"有望""前景广阔""随着……的发展"。
- [ ] 开篇不是背景铺垫。
- [ ] 核心结论句 <= 25 字。
- [ ] 无纯过渡段（无数据、无判断、无信息增量的段落）。

## 复核结果处理

| 结果 | 处理 |
|---|---|
| 全部通过 | 进入 Step 7 输出 |
| 事实性不通过 | 回退 Step 3（采素材）补采对应数据 |
| 完整性不通过 | 回退 Step 2（搭大纲）补章节，或 Step 4（加工素材）补内容 |
| 读者视角不通过 | 回退 Step 5（写正文）改写风格/调整篇幅 |
| 逻辑一致性不通过 | 回退 Step 5（写正文）修正结论或分析 |
| 写作质量不通过 | 回退 Step 5（写正文）润色 |

## `review_checklist.md` 格式

```markdown
# 复核清单

## 总结
- 复核结果: [通过/不通过]
- 必须回退: [是/否]
- 回退步骤: [Step X]
- 主要问题: [...]

## 逐项检查
| 维度 | 检查项 | 结果 | 严重程度 | 修正建议 | 回退步骤 |
|---|---|---|---|---|---|
| 事实性 | 所有数字标注来源 | 通过/不通过 | 高/中/低 | ... | Step 3 |
```

## 质量卡口

- [ ] 复核清单已逐项检查，无遗漏。
- [ ] 不通过项已明确标注问题类型和修正建议。
- [ ] 严重不通过（事实性/逻辑一致性）已标记为"必须回退"。

未通过时，将 `review_checklist.md` 交给 orchestrator 执行回退。
