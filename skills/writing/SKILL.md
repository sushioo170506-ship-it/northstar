# Content Writing

独立实现：`research_workflow.skills.writing.WritingSkill`。

输入需求简报、writing_standards、议题树、最终大纲、调研包、证据账本、章节素材和可视化资产，输出
`SkillResult(artifact_type="draft")`。写作必须区分事实、分析和建议，只使用治理后的来源；
每个事实章节附原始 URL，以 Mermaid/Vega-Lite 代码块嵌入可视化规范。资料不足使用显式缺口
标记。实现按章节生成，可处理十万字级目标。

```python
result = WritingSkill(generator=my_generator).execute(request)
```

模型适配器应支持按章节设置 token 上限。输出后进入 `draft_confirmation`；针对初稿的
修改仅重跑写作、排版、审核及中间确认。

## 职责边界

只负责“怎么写”。章节和核心判断来自 outline；可用论断、分级、评分来自 data_processing；
图表来自 visualization。不得新增来源、改分、改图中数据或重排已确认章节。
技术、投研、公众号、官方内参的结构、术语、公式、估值、互动和公文规则来自版本化
writing_standards产物，不得仅依赖自由文本style猜测。

## 判断驱动写作规则

1. 开篇第一句必须是反常识数字、证据冲突或可证伪判断，禁止背景铺垫。
2. 每节首段给 chapter_claim 和最强锚点；只读节首应获得全文主要逻辑。
3. 一段只承担判断/发现/对比/机制/反证/局限/含义之一，4–8 句。
4. 关键数字首次出现必须含数值、时间、来源、单位/口径；随后一句解释“这意味着什么”。
5. 若用户显式启用竞争性假说，按“共识→支持证据→反证→修正判断→成立边界”闭环；
   未启用时只回答大纲问题和情景条件。
6. 因果词与证据强度匹配；观察相关不得写成导致。

## 禁止表达

删除“随着……的发展、在当今世界、近年来、有望、未来可期、前景广阔、取得突破、颠覆式、
风口、赛道、弯道超车”等无数据判断。核心判断≤25 字；常规句 20–50 字；纯过渡句删除。

## 数据与引用

- 只引用 claim.status=supported 且 grade≠D 的内容。
- 关键论断优先 A+/A；仅 B/C 时显式降级。
- 每个数字引用 original_url；厂商自评标立场；社区案例标样本限制。
- 来源链接必须出现在支撑该判断的正文段落或对应章节，文末参考文献不能替代内联引用。
- scoring=not_applicable 时不得在正文创造排名。

## 错误与退回

- 缺章节锚点：退回 data_processing/research，不用套话填充。
- claim 冲突：并列口径与边界，退回 data_processing。
- 篇幅超限：先删背景和重复，不删核心判断、锚点、局限和证伪条件。
- 初稿完成后必须进入 pressure_test，不可直接 formatting。

## 风险章节聚焦规则

- 模型报告：只讨论模型能力边界、幻觉、鲁棒性、安全、隐私、成本和部署风险。
- ETF/基金报告：只讨论成份集中、估值回撤、流动性、折溢价、跟踪误差、盈利和政策周期。
- 产业报告：讨论需求、供给、技术替代、竞争、政策和财务风险。
- “本文信息可能不完整”只能放在方法局限，不得替代研究对象本身的风险分析。
